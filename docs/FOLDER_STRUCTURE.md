# Project Folder Structure

## Why This Structure

- **Simple separation** of concerns (Frontend vs Backend)
- **Docker-compose** orchestrates both services
- **One repository** for easy coordination
- **Easy to deploy** independently to Vercel (FE) and Render (BE)

See [ARCHITECTURE_DECISIONS.md](ARCHITECTURE_DECISIONS.md#16-project-structure-simple-folders-vs-monorepo) for decision rationale.

## File Descriptions

### Frontend (`frontend/src/`)

| File | Purpose |
|------|---------|
| `main.tsx` | React app entry point |
| `App.tsx` | Root component, routing |
| `pages/LandingPage.tsx` | Home page (Create List button) |
| `pages/ListPage.tsx` | Main app (show items, add, delete) |
| `components/ItemList.tsx` | Render list of items |
| `components/AddItemForm.tsx` | Input + price + Add button |
| `components/ItemRow.tsx` | Single item (checkbox, text, price, delete) |
| `components/TotalCost.tsx` | Display total + progress |
| `hooks/useFetch.ts` | Custom hook for API calls |
| `types/index.ts` | TypeScript types (List, Item, etc) |
| `utils/api.ts` | API client (fetch wrapper) |
| `styles/globals.css` | TailwindCSS config + global styles |

### Backend (`backend/src/`)

| File | Purpose |
|------|---------|
| `index.ts` | Express app setup, server start |
| `routes/lists.ts` | POST/GET /lists endpoints |
| `routes/items.ts` | POST/PATCH/DELETE /items endpoints |
| `middleware/cors.ts` | CORS configuration |
| `middleware/logging.ts` | Request logging |
| `middleware/errorHandler.ts` | Global error handling |
| `services/listService.ts` | Business logic for lists |
| `services/itemService.ts` | Business logic for items |
| `types/index.ts` | TypeScript types (interfaces) |
| `utils/validation.ts` | Input validation rules |

### Prisma Schema

| File | Purpose |
|------|---------|
| `prisma/schema.prisma` | Database schema definition |
| `prisma/migrations/` | Auto-generated migration files |

## Git Ignore

Both `frontend/` and `backend/` should have `.gitignore`:

```
node_modules/
dist/
.env
.DS_Store
*.log
```

---

## Scaling Beyond v1

**If v2 needs shared code:**

Option 1: Add shared folder
```
libs/
├── shared-types/     # TypeScript types for both FE & BE
└── shared-utils/     # Common utilities
```

Option 2: Extract backend types for frontend
- Backend generates type definitions
- Frontend imports types from backend (via API client generation)

**Until then:** Keep it simple, no shared code.
